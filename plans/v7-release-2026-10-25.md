## Context

Complete PR #101's hard token rename, update its consumers and migration guide, and ship the accessibility fixes with minimal rendering changes. The existing feat/v7 checkout combines these changes, so one reviewed PR into develop carries the complete 7.0.0 cut. No compatibility aliases are retained.

## Changes

1. Finish semantic colour, spacing and typography token names in source CSS, examples, kitchen sink, skills and docs. Keep font-serif, focus-ring width/offset and breakpoint names.
2. Use zero-specificity light defaults; preserve dark values and classless dark focus colour when utilities load later.
3. Restore keyboard focus on buttons, radios, checkboxes, utility buttons and aria-disabled controls. Add forced-colour outlines to focused fields; retain contrast-more behaviour.
4. Darken light captions and muted text to 118 grey, and field, control and table borders to 138 grey. Preserve dark values.
5. Publish the complete v6-to-v7 migration mapping, dark override rules, CDN pin guidance, API reference and documentation links.
6. Cut package and lockfile version 7.0.0, skill ranges >=7.0.0 <8.0.0, kitchen-sink cache-busters 700, archive links, changelog, CSS builds, SRI and skills snapshots.
7. Verify local gates, new browser regressions, full build/page/scheme comparisons and desktop/mobile screenshots. Push PR #101's head by fast-forward, then require green Node 20/22 and browser CI before marking ready.
8. Merge into develop, publish npm 7.0.0, verify all CDN hashes, merge the develop-to-main release PR, verify docs deployment, create annotated v7.0.0 and its GitHub release, and fast-forward develop to the resulting main commit. Do not back-merge main.

## Rollback

If CDN hashes or live documentation checks fail, hold promotion. After deployment, revert the release through a PR and redeploy the previous tag. Consumers can pin bullframe.css@6; npm versions are immutable.
